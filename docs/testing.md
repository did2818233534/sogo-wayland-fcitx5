# 验证记录与复测

开发环境：Ubuntu 24.04 / GNOME Wayland / x86_64 / Fcitx5 5.1.7。

移入仓库前的版本通过隔离 D-Bus/Fcitx 输入检查：60 次连续提交、切换输入法、退格、Escape、引擎崩溃后重启、四方向选词、跨页选词、英文标点和 Shift。联网检查覆盖 nohao → 你好、云候选提交、丢弃过期响应、方向键冻结、翻页、输入框销毁。网络隔离时本地候选仍正常。测试子进程已清理。

未完成 Chrome 原生 Wayland 实际键盘输入的人工端到端验证。引擎挂起测试观察到的是服务断开后恢复，不将其称为精确的超时测试。

本仓库 `make check` 是部署工具测试与归档校验，不冒充上述完整集成测试。原始集成工具依赖开发机的隔离挂载环境，未将其中的个人路径、词库和日志直接复制进仓库。

发布前建议在干净的 Ubuntu 24.04 VM 中按 README 安装，并人工复测：

1. `nihao` 的五个候选和数字/空格提交。
2. 第五项再右/下进入下一页，第一项再左/上回上一页末项。
3. 逗号、句号翻页，清空输入后正常输出标点。
4. nohao 云候选、断网本地候选、快速输入后取消无旧候选回填。
5. 切换窗口和输入法，服务重启后恢复。
6. Chrome Wayland 与其他文本编辑器的实际输入。
7. 卸载后其他输入法仍正常，个人词库保留，系统链接移除。

当前机器保留现有安装，仅验证新项目构建与非破坏性检查；没有在当前桌面重复运行新系统安装/卸载流程。

## 翻页后选词索引回归（2026-10-10）

修复了翻页后仍提交第一页同位置候选的问题：CPIS `SelectCandidate` 的 index 是全部候选中的零基索引，因此需使用 `page * 5 + localIndex`。例如第二页第三项为索引 7。选择候选后引擎重置候选页，适配层同步重置页码。

隔离 Fcitx D-Bus 实测：输入 `hao`，分别翻到第二、第三页，记录实际显示的第三项，分别通过数字 `3`、右方向键两次加空格提交，断言 CommitString 与显示文本完全一致。四组检查通过，原有跨页方向键、返回上一页末项和标点检查也通过。使用单音节测试避免把引擎的分段预编辑误判为完整提交；多音节选择部分候选后可能继续等待剩余拼音。

## 输入延迟与首字母超时回归（2026-10-27）

运行 `/usr/bin/python3 tests/integration_timeout.py`，脚本自动创建独立 D-Bus 会话和临时 Fcitx 配置，退出时回收测试进程及临时目录。使用模拟 CPIS 引擎，云候选关闭；不使用桌面正在输入的上下文。

验证连续 10 次 nihao 空格提交；SetMode 只调用一次；模拟 PushChars 阻塞 550 ms 时，首键约 180 ms 返回，后续四键低于 1 ms，不提前提交 n，完整 nihao 在自动重放后可提交；验证超时期间退格与 Escape 取消。此测试覆盖适配层的超时恢复，不证明闭源引擎内部阻塞原因，也不替代桌面实际输入体验验证。

## 卡顿诊断日志

适配器默认将超过 30 ms 的调用、失败调用与慢操作写入 stderr（当前桌面自启动由用户 journal 收集），包含 op 关联号、方法名、耗时、预算、错误分类和 D-Bus 错误域/代码。恢复尝试记录 recovery_start/recovery_ok/recovery_failed。不记录按键值、拼音、候选词或提交内容。超时说明本机引擎未及时回复，不代表已确定闭源引擎内部根因。

运行 `/opt/sogou-ng/export-diagnostics.py` 将最近 15 分钟的适配器与引擎 journal 导出到 `/opt/sogou-ng/logs/diagnostics-时间.log`，文件权限为 600。可传入 `"1 hour ago"` 改变时间范围。日志持续存储由系统 journal 管理；导出文件仅在手动运行脚本时生成。

集成测试额外断言超时方法、原因、操作耗时与恢复事件存在，且不包含测试输入文字。
